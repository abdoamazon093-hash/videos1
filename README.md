# Videos1 - Strict Versioning & Rollback Architecture

منصة وتطبيق بايثون متكامل مبني باستخدام FastAPI مع كاش محلي فائق السرعة عبر SQLite، ومحمية بنظام إدارة الإصدارات والرجوع التلقائي الصارم المتصل بـ GitHub.

---

## 🔒 قواعد الأمان وحماية الأسرار (Security Policy)
- **عزل تام للأسرار:** كافة مفاتيح الـ API والمتغيرات الحساسة مخزنة محلياً فقط في ملف `.env`.
- **ملف `.gitignore` الصارم:** يمنع رفع أي ملف `.env` أو نسخ احتياطية لقواعد البيانات `*.db`, `*.sqlite`, ومجلدات البيئة الافتراضية `venv/`.
- **نموذج الإعدادات `.env.example`:** ملف مرجعي نظيف وخالي تماماً من الأسرار لتوضيح أسماء المتغيرات المطلوبة.

## ⚡ أدوات الأتمتة المتاحة على السيرفر (CLI Commands)

### 1. حفظ إصدار جديد ورفعه تلقائياً:
```bash
save-version "رسالة الالتزام"
```
- يقوم بتشغيل الاختبارات الآلية `pytest tests/`.
- يفحص عدم وجود ملفات سرية مضافة.
- يجمع التعديلات (`git add -A`).
- يحسب رقم الإصدار التسلسلي التالي تلقائياً (`v1, v2, v3...`).
- ينشئ التاج المقابل (`git tag vX`).
- يرفع الفرع الرئيسي والتاج فوراً إلى مستودع GitHub.

### 2. الرجوع الآمن بالزمن (Byte-for-Byte Rollback):
```bash
rollback-version v1
```
- يعيد جميع ملفات المشروع لتتطابق بنسبة 100% مع التاج المطلوب دون أي تخمين.
- يوثق الرجوع بالتزام (`commit`) ويرفعه فوراً إلى GitHub.
- يعيد تشغيل خدمة النظام `videos1.service` تلقائياً لتطبيق التغييرات.

---

## ⚙️ خدمة النظام (Systemd Service)
يعمل المشروع تلقائياً في الخلفية على المنفذ `8095`:
```bash
# حالة الخدمة
systemctl status videos1.service

# إعادة تشغيل
systemctl restart videos1.service

# متابعة السجلات الحية
journalctl -u videos1.service -f
```
